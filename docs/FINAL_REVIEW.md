# 채용 포트폴리오 최종 검토

검토일: 2026-10-23. 공개본과 로컬 개선본을 구분한다. 마지막 사용자 요청에 따라 확인된 개선만 로컬 적용했고 commit·push·배포는 하지 않았다.

## 판단 기준

1. 첫 화면에서 지원 방향·실무 경험을 이해하고, 실무와 학습을 혼동하지 않는가.
2. 상세를 읽은 면접관이 본인 역할·설계 이유·문제 해결·검증 한계를 코드와 대조할 수 있는가.
3. 모바일에서 근거 이미지와 본문을 읽고, 상세 → 이력서 → 연락으로 진행할 수 있는가.
4. 이미지·영상·PDF·독립 주소가 실제로 동작하고, 수정·배포 때 사실이나 비공개 자료가 잘못 노출되지 않는가.

## 결론

**로컬 개선본은 공개 가능한 수준이다.** 현재 공개본은 경력과 프로젝트 소개의 기본 목적을 달성하지만, 적극적인 채용 공유 전 아래 기술 표현과 모니터링 영상 문제를 반영하는 것을 권한다. 사이트 전체를 내리거나 재설계할 정도의 결함은 발견하지 않았다.

## 실제 문제와 조치

| 우선순위 / 위치 | 재현·근거 | 영향 / 처리 |
|---|---|---|
| 공개 전 수정: 재활용 상세 `#design` | 기존 제목 “영상에서 실제 배출 이벤트로”. Qt `controllers/recycle_session_controller.cpp`는 `!m_doorWasOpen && meta.door.isOpen`으로 집계한다. MCU `recycle.c`는 개방 요청 시 `s_gate_state=GATE_OPEN`을 설정하고 이후 모터 진행을 처리한다. 실제 물체 낙하 감지를 입증하는 흐름은 아니다. | 면접관에게 실제 투입 검증 기능으로 읽힐 수 있다. 로컬은 “영상 검출과 도어 상태 집계를 분리”로 바꾸고 실제 낙하를 별도로 검증하지 않았음을 명시했다. 소스 저장소는 수정하지 않았다. |
| 공개 전 수정: 모니터링 상세 상단 영상 | 공개본은 기존 GitHub HEVC 첨부 링크. 이번 Chromium 재시험에서 10초 뒤 readyState=0, currentTime=0. 로컬 H.264 사본은 readyState=4, 시간 진행 확인. | 대표 시연을 열어도 재생되지 않는 환경이 있다. 이전 작업의 H.264/AAC 720p 로컬 링크 수정을 유지했고 공개본에는 아직 없음을 확인했다. 모든 브라우저에서 실패한다고 단정하지 않는다. |
| 권장 개선: 모바일 상세 이미지 확대 | 390px 화면에서 Qt 이미지 너비 330px → dialog 331.48px. 확대 기능의 실질적 효과가 거의 없다. | 화면 속 작은 글자를 읽기 어렵다. 로컬에 2배 확대/화면 맞춤, 스크롤, 이미지 파일 직접 열기를 추가했다. 수정 후 338.48px → 676.97px 확인. |
| 권장 개선: 상세 읽기 종료 지점 | 기존 상세 하단에는 프로젝트 목록 복귀만 있고 모바일 고정 헤더의 이력서·연락처는 메뉴 안에 숨겨진다. | 관심을 가진 방문자가 메뉴를 다시 찾아야 한다. 상세 하단에 이력서와 이메일 링크를 추가했다. 신규 화면이나 문의 서버는 추가하지 않았다. |
| 권장 개선: 설명의 시점·중복 | “이번 사이트 제작 중”, “이번 작업에서”처럼 제작자의 검토 과정이 방문자용 문제 해결·검증 설명에 반복된다. | 지원자의 프로젝트 설명에서 벗어난다. 이를 최종 실물 재검증·공개 계측 근거의 범위로 간결하게 바꿨다. 검증 한계 자체는 유지했다. |
| 작은 구현 보완: 이미지·조작 영역 | 기존 img의 intrinsic width/height 미지정, 모바일 메뉴·목차의 여유가 작음. | 로딩 전 공간 확보를 위해 이미지 크기를 명시하고 모바일 조작 여백을 늘렸다. 실측 성능 향상률이나 WCAG 위반이었다고 주장하지 않는다. |

## 유지한 선택과 채용 관점 평가

- 첫 화면의 약 3년 경력, 경력 영역의 회사·기간·구체 업무, 교육 프로젝트의 구분은 적절하다. Linux 응용 SW 실무를 드라이버 실무로 확대하지 않는다.
- 선풍기 → 재활용 → 모니터링 순서는 각각 장애 대응·시스템 통합·MCU 원격 제어로 연결된다. 동일한 기술 목록만 반복하는 구성은 아니다.
- 지아이티의 통신·센서 연동, 브이유텍의 변전소 2곳 적용은 연락할 이유가 되는 구체적 경험이다. 근거 없는 개선율·FPS·숙련도 막대를 보태지 않았다.
- 밝은 배경·짙은 텍스트·파란 강조, 실제 이미지, 독립 상세 주소를 유지한다. 화려함 부족은 결함으로 보지 않는다.
- 모바일 메인은 약 8,000px로 길지만 경력·프로젝트·연락처 바로가기가 있고 확정 구성에 따른 길이다. 무조건 축약하거나 카드 수를 줄일 필요는 없다.
- HTML 생성기 한 파일에 데이터와 템플릿이 섞여 있으나 현재 3개 대표작 규모에서는 전면 재설계 이유가 없다. 수정 원본과 생성 명령을 README에 명시한 방식은 유지한다.
- 정확한 프로젝트 기간은 미확정이라 생략했다. 추정 날짜보다 낫고 공개 차단 사항은 아니다. 후속 확인 시 추가하면 시간적 맥락이 좋아진다.

## 공개본과 로컬의 차이

검토 시작 당시 줄바꿈을 정규화하면 메인·선풍기·재활용 HTML은 동일했고, 모니터링만 영상 링크가 달랐다. 단순 바이트 비교의 차이를 모두 내용 차이로 판정하지 않았다.

현재 로컬에는 위의 문구·이미지 확대·연락 동선·이미지 크기 개선이 추가되어 있다. 공개본에는 이 변경이 없다. 공개 PDF는 로컬 제공 원본과 바이트가 동일하다. 공개 `_handoff/START_HERE.md`, `_handoff/resume.pdf`는 모두 404이며 Git 추적에도 `_handoff`는 없다.

## 실제 검증

- Chromium 156 실제 브라우저: 공개/로컬 4페이지의 390px·1440px 탐색·캡처, HTTP 200·가로 넘침·콘솔·PDF 확인.
- 로컬 개선 후 320·390·768·1440px 16개 조합 회귀 검사. 확대/축소, Escape, 포커스 복원, 메뉴·직접 주소·새로고침·뒤로가기·no-JS·내부 링크 검사.
- axe-core 4.10.3: 공개/개선본 각 4페이지, 모바일, WCAG 2 A/AA·2.1 AA·2.2 AA 태그 검사에서 위반 0. 자동 검사 통과는 접근성 완전 인증이 아니다.
- 외부 링크 15개 HTTP 200. 모니터링 공개 영상과 로컬 사본의 재생 상태 비교. 다른 두 영상의 이전 재생 결과는 기존 검증 기록 참조.
- 6개 프로젝트의 현재 원격 HEAD가 확보한 소스와 동일함을 read-only 조회. 이력서 경력·명세·README·검증 문서·재활용 발표자료 및 관련 코드 대조.
- 공개 메인 초기 resource 관측에서 CSS·JS는 압축 전송되며 관측된 이미지 3개 합계 약 327KB, 폰트/CDN/자동 재생 영상 요청 없음. 이는 Lighthouse 점수·느린 이동통신 성능 보장이 아니다.
- 근거: `_handoff/final-review/`의 audit.json, revisions.json, accessibility.json, video-comparison.json 및 공개/개선 캡처. 회귀 결과는 `_handoff/qa/`.

## 미확인 범위

실물 iOS/Android, Safari/Firefox, 스크린리더 전체 조작, 이동통신 속도·실사용 Core Web Vitals, QR 인쇄물 스캔은 확인하지 않았다. 해당 기기·실사용 데이터가 없기 때문이다. GitHub Pages 관리 화면/빌드 설정은 변경하거나 검증하지 않았으며 공개 HTTP 동작만 확인했다. 하드웨어 시험·프로젝트 전체 빌드·성과의 독립 재측정은 이 웹사이트 검토 범위가 아니다.
